## React Hooks 深度使用测试

在最近的项目中，我深入测试了 React Hooks 的各种使用场景。

### useEffect 优化实践

```typescript
import { useEffect, useCallback, useMemo } from 'react'

interface DataFetcherProps {
  userId: string
  refreshTrigger: number
}

const DataFetcher: React.FC<DataFetcherProps> = ({ userId, refreshTrigger }) => {
  const [data, setData] = useState(null)
  const [loading, setLoading] = useState(false)

  const fetchData = useCallback(async () => {
    setLoading(true)
    try {
      const response = await api.getUserData(userId)
      setData(response.data)
    } catch (error) {
      console.error('获取数据失败:', error)
    } finally {
      setLoading(false)
    }
  }, [userId])

  useEffect(() => {
    fetchData()
  }, [fetchData, refreshTrigger])

  const memoizedData = useMemo(() => {
    return data ? processData(data) : null
  }, [data])

  return (
    <div>
      {loading ? '加载中...' : memoizedData}
    </div>
  )
}
```

### 测试结果

通过测试发现：
- `useCallback` 确实能减少不必要的重渲染
- `useMemo` 对计算密集型操作效果显著
- 依赖数组的管理是关键

## TypeScript 高级类型实验

### 条件类型的实际应用

```typescript
// 根据输入类型自动推断返回类型
type ApiResponse<T> = T extends string
  ? { message: T; status: 'success' }
  : T extends number
  ? { code: T; status: 'error' }
  : { data: T; status: 'ok' }

// 实用的工具类型
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P]
}

// 从对象类型中提取函数类型
type FunctionKeys<T> = {
  [K in keyof T]: T[K] extends Function ? K : never
}[keyof T]

interface UserService {
  getName(): string
  getAge(): number
  setName(name: string): void
  isActive: boolean
}

type UserMethods = FunctionKeys<UserService> // "getName" | "getAge" | "setName"
```

### 类型体操的实际价值

经过测试，我发现：
1. **类型安全性提升显著** - 编译时就能发现大部分错误
2. **开发体验改善** - IDE 智能提示更准确
3. **代码可维护性增强** - 重构时类型系统会指出所有需要修改的地方

## CSS-in-JS vs CSS Modules 对比测试

### Styled Components 测试

```typescript
import styled, { css } from 'styled-components'

const Button = styled.button<{ variant: 'primary' | 'secondary' }>`
  padding: 12px 24px;
  border-radius: 6px;
  font-weight: 600;
  transition: all 0.2s ease;

  ${props => props.variant === 'primary' && css`
    background: #3b82f6;
    color: white;
    border: 2px solid #3b82f6;

    &:hover {
      background: #2563eb;
      border-color: #2563eb;
    }
  `}

  ${props => props.variant === 'secondary' && css`
    background: transparent;
    color: #3b82f6;
    border: 2px solid #3b82f6;

    &:hover {
      background: #3b82f6;
      color: white;
    }
  `}
`
```

| 方案 | Bundle Size | Runtime Performance | DX |
|------|-------------|---------------------|-----|
| Styled Components | +15KB | 较慢 | 优秀 |

| Utility-First (UnoCSS) | +5KB | 最快 | 非常好 |

## 状态管理方案测试

### Zustand vs Redux Toolkit

经过在中型项目中的实际使用测试：

**Zustand (推荐)**
```typescript
import { create } from 'zustand'
import { devtools, persist } from 'zustand/middleware'

interface UserStore {
  user: User | null
  isLoading: boolean
  login: (credentials: LoginCredentials) => Promise<void>
  logout: () => void
}

const useUserStore = create<UserStore>()(
  devtools(
    persist(
      (set, get) => ({
        user: null,
        isLoading: false,
        login: async (credentials) => {
          set({ isLoading: true })
          try {
            const user = await authApi.login(credentials)
            set({ user, isLoading: false })
          } catch (error) {
            set({ isLoading: false })
            throw error
          }
        },
        logout: () => set({ user: null })
      }),
      { name: 'user-store' }
    )
  )
)
```

**优势：**
- 代码量减少 60%
- 类型安全性更好
- 学习成本低
- 性能优秀

## 测试工具链实践

### Vitest + Testing Library

```typescript
import { render, screen, fireEvent, waitFor } from '@testing-library/react'
import { describe, it, expect, vi } from 'vitest'
import { UserProfile } from './UserProfile'

describe('UserProfile', () => {
  it('应该正确显示用户信息', async () => {
    const mockUser = {
      id: '1',
      name: '张三',
      email: 'zhangsan@example.com'
    }

    render(<UserProfile userId="1" />)

    // 等待异步数据加载
    await waitFor(() => {
      expect(screen.getByText('张三')).toBeInTheDocument()
    })

    expect(screen.getByText('zhangsan@example.com')).toBeInTheDocument()
  })

  it('应该处理编辑操作', async () => {
    const onSave = vi.fn()
    render(<UserProfile userId="1" onSave={onSave} />)

    const editButton = screen.getByRole('button', { name: '编辑' })
    fireEvent.click(editButton)

    const nameInput = screen.getByLabelText('姓名')
    fireEvent.change(nameInput, { target: { value: '李四' } })

    const saveButton = screen.getByRole('button', { name: '保存' })
    fireEvent.click(saveButton)

    await waitFor(() => {
      expect(onSave).toHaveBeenCalledWith({
        ...mockUser,
        name: '李四'
      })
    })
  })
})
```

## 总结与反思

通过这次全面的技术栈测试，我得出以下结论：

### 技术选型建议

1. **前端框架**: React + TypeScript 仍然是最稳定的选择
2. **构建工具**: Vite 在开发体验和性能间取得了很好的平衡
3. **状态管理**: 小项目用 React Context，中大型项目推荐 Zustand
4. **样式方案**: Utility-First CSS (UnoCSS/Tailwind) + CSS Modules 混合使用
5. **测试工具**: Vitest + Testing Library + Playwright

### 未来探索方向

- **Web Components** 的标准化进展
- **Server Components** 在复杂应用中的应用
- **边缘计算** 对前端架构的影响
- **WebAssembly** 在前端性能优化中的应用
